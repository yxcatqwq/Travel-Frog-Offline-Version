# M2 待确认游戏机制

本文集中记录目前缺少服务端依据、暂按临时规则实现的机制。后续拿到在线版数据或产品确认后，只需修改对应规则和迁移逻辑。

| 机制 | 当前临时规则 | 需要确认的问题 | 人工维护的机制答案 |
|---|---|---|---|
| 相册初始容量 | 新存档 30 页；只计算已保存照片 | “页”是照片数量还是分页容量？待保存照片是否占用容量？ | 是分页容量，待保存不占用，如果拒绝保存会自动放入回收站； |
| 相册扩容 | 每次默认增加 10 页，消耗 50 四叶草（5/页） | 扩容档位、价格、是否有上限、是否使用铃铛或广告 | 扩容是在商店卖的。每买一个，增加一页。每8页一组，价格为波动售价，1000-1250-1500-2000-3000-2000-1500-1250。最多额外购买 56页。 |
| 回收站 | 删除照片进入回收站，可恢复；恢复照片需重新占用容量 | 回收站保留时长、容量和过期清理规则 | 回收站只有六个位置，不会过期，超出六个自动删除 |
| 旅行时长 | 诊断入口默认 60 秒；实际旅行沿用目的地 duration | 各目的地时长、是否受便当/道具影响 |  |
| 旅行奖励 | 基础四叶草 10，每件行李额外 2，最多 30 | 奖励表、稀有照片概率、事件顺序 |  |
| 礼物盒 | 旅行照片先进入礼物盒，用户可转入相册或物品栏 | 礼物盒容量、照片是否同时出现在“新照片”列表 | 不会，照片放进礼物盒就不会出现在相册里了 |
| 邮件 | 本地保存邮件正文和附件，无自动过期 | 邮件过期时间、已读状态和附件领取后是否可重复领取 | 不会过期，读完就看不到了，附件当然不可以重复领取 |
| 胡萝卜/幸运草 | 按配置表决定成熟时间和产量 | 离线结算精度、季节/天气修正 | 每棵草是被摘掉后 15min-3h 之间随机一个时间长出，因此理论每 3h 三叶草田就会满 |
| 堆肥箱 | 沿用当前本地倒计时和产出字段 | 配方、完成时间、产物数量及是否允许中途取出 |  |
| 花盆 | 暂沿用存档中的生长字段 | 生长阶段、浇水规则、收获奖励 |  |
| 工作台与家具 | 家具购买已本地扣除货币并持久化 | 配方解锁、制作时间、失败/取消规则 |  |
| 天气与季节 | 使用本地时钟和配置快照 | 时区、切换时刻、天气对旅行和植物的影响 |  |
| 在线存档导入 | 导入内容覆盖本地同名状态，保留本地格式版本 | 冲突字段优先级、重复照片 ID、无效道具处理 |  |

以上规则均标记为“临时”，不会阻塞存档导入导出；确认后应补充迁移版本号和回归测试。
