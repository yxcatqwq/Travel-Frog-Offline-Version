对应需求文档：[本地服务实现清单.md](本地服务实现清单.md)。

在 `main.min.js` 之后加载，运行时接管 `core.SocketManage` 的网络路径。

## 2. 状态与存档

- 存档 key：`frog_local_save_v1`，备份 `frog_local_save_v1_backup`，写前临时 `..._tmp`，
  坏档另存 `frog_local_save_v1_corrupt_<时间戳>`。
- 分区：`header / clock / rng / role / settings / wallet / items / furniture / tumbler /
  compost / pocket / flowerpot / clover / weather / tasks / mail / events / decorate /
  journal / scheduler`。
- 所有改动经过 `LF.tx.commit()`：一次操作 = 一次校验 = 一次落盘 = 一次推送。
- 幂等：请求带 `session` 时以 `协议#session` 作为 opId，重复投递只结算一次。

## 3. 数值与规则的来源

- 草田再生周期：客户端 `CloverFarm` 常量（`clover_mu=7200`、`clover_sigma=1800`、
  `cloverSpanMin=300`、`cloverSpanMax=14400`、四叶草 0.5%）。
- 草位成熟判定与客户端一致：`last_harvest <= 0` 或 `last_harvest + rebirth_span <= now`；
  生长中的草位是 `last_harvest > 0` 且未到再生时间（`-1` 是客户端“刚采完”的本地标记）。
- 抽奖概率：`Tabikaeru.Define.PrizeBalls`（白 40 / 蓝 25 / 紫 22 / 绿 9 / 红 3 / 金 1），
  消耗 `RAFFEL_NEEDTICKETS=5`；中奖名次与候选奖品持久化，领奖走 `item_redeem_prize` 校验。
- 新档赠送：全部来自包内配置（首个堆肥箱/不倒翁/口袋、FURNITURE_TOOL/ITEM/LunchBox 条目），
  不硬编码 id，并写入 `header.starterKit` 便于审计。
- 口袋积累：本地规则「每 30 分钟 +1，上限 `pocketCommonData.base_info`」，属待核对项。
- 错误码沿用包内 `errcode_json`（5 参数非法、6 非法操作、41 空间不足、42 物品不足、
  61 资源不足）；未实现协议返回 1（通用错误）并记入诊断清单，不伪造成功。

## 4. 兼容客户端既有缺陷的处理

| 现象 | 客户端原因 | 本地服务处理 |
|---|---|---|
| 堆肥箱有数据不显示 | `furniture_load_compost` 派发 `UPDATE_TUMBER`，主场景订阅 `UPDATE_COMPOST` | 推送后补发 `UPDATE_COMPOST` |
| 点开商人崩溃 | 货架项缺 `item_id`，渲染器取 `ItemDB.get(undefined).img` | 货架项写入 `shop_id/item_id/num`；`state.validate` 会下架无法解析的条目 |
| 场景创建崩溃（花盆） | `show_list` 的 `type` 越界导致 `flowerpotList[type]` 为 undefined | 新档只“拥有”花盆不默认摆放；视图刷新逐项 try/catch |
| 教程/引导反复出现 | 本地推送回灌了旧的 `settings.client` | `client_load_role` 不再下发 client 设置（由 `client_set_client` 单向入库） |
| 进游戏弹微信分享 | `album_load_new` 的 `is_share` 为 true 触发在线分享流程 | 占位数据固定 `has_ads=false / is_share=false`（D03/D05） |
| 打开宝箱/看广告类入口 | P3 在线能力 | 明确失败并记录，不做假成功 |
